Цель пользователя: «C++ только связь с ОС». Состояние на начало ветки — ≈31 тыс. строк C++ (include/vish/*.hpp, src/vish.cpp).

**Развилка (решение автора):** вычислитель на самом себе требует «семени». Варианты: (А) бутстрап-образ — интерпретатор и машина на vish, JIT-компилятором (на vish) собираются в машинный образ, коммитится как `vish.image`; C++ = загрузчик + системные вызовы (≈2–3 тыс. строк). Нужен полный JIT над конструкциями вычислителя. (Б) только тулинг-логика на vish, ядро вычислителя остаётся C++ как «бутстрап» (так записано в docs/status.md): цель «только ОС» не достигнута полностью. (В) Б, затем А.
 (нужен базовый язык и бутстрап).

## Ход переноса (решение автора 2026-11-10:)

Приём каждого шага: версия на vish (встроенный модуль lib/*.vish) + `native` с C++-эталоном (stage0) + команда сверки, которая
сравнивает построчные дампы на всём корпусе (lib/*.vish, tests/*.vish, граничные тексты tests/data/); C++-версия остаётся, пока
вычислитель не собран из образа.

| Шаг | Что | Проверка | Состояние |
|---|---|---|---|
| 1 | лексер (lib/lexer.vish, 181 строка C++) | `vish lexcheck` — 341 файл + 7 граничных, расхождений 0 | сделан |
| 2 | фаза 1 парсера: имена `ast.*`, починка скобок по отступу, таблица парных (lib/parser.vish) | `vish parsecheck` — 292 файла + 5 граничных (несбалансированные скобки), расхождений 0 | сделан |
| 3+ | фаза 2 парсера: операторы, цепочки, конструкции, раскладка комментариев; построение узлов (нужны примитивы создания узлов на языке) | дамп `vish ast` против C++ | не начат |
| … | printer, modules, views, session, proto, server (логика) | эквивалентные дампы/протокол | не начат |
| образ | интерпретатор и машина на vish → JIT-компилятор (на vish) → `vish.image`, C++ — загрузчик и системные вызовы | загрузка образа вместо C++-вычислителя | не начат; требует JIT над конструкциями вычислителя |

Замеры: лексер vish ≈90 с на 341 файл (1,4 МБ) в интерпретаторе, из них sys ≈60 с — постраничная работа с памятью (рост массивов токенов); парсер фазы 1 — 5 мин на 292 файла. Для рабочего использования нужны JIT этих функций и дешёвый рост массивов. Это условие перехода на vish-версию как основную.

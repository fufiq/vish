## Дополнение: причина и результат (вторая сессия)

Бисекция по коммитам (release, `taskset -c 3 vish test tests/64_editor_complete.wire`, 3 прогона):
`e533672` (Ш1) 0,79–0,86 с — регресса нет; `8cefa3b` (слияние Ш2: текстовые функции с native на vish)
1,81–1,84 с; `8682be0` (быстрые пути) 1,62–1,63 с; HEAD + правки до этой сессии 1,32–1,41 с.
Причина — перенос текстовых/сортировочных примитивов на язык: счётчик вызовов (временный, не
оставлен) показал на сценарии 64 ≈220 тыс. вызовов функций Vish, из них `push` 82 тыс. (37%),
`key_less` 28 тыс., `describe_value` 14 тыс., `text_byte` 11 тыс., `escape_from`/`in_quotes` по 10 тыс.
Микробенч 400 тыс. `xs.push(i)`: 0,59 с, а `append(xs, i)` 0,29 с — обёртка прелюдии
`push(mut xs, x) => append(xs, x)` стоила втрое больше самой операции.

Правка (*моё*, узкая VM-оптимизация): `interpreter::push_is_append` + быстрый путь в `eval_node(n_call)`
для `push(xs, x)` и `xs.push(x)` при исполнении без JIT и при единственной `push` вида обёртки над
`append` — вызывается тот же `append`. Разбор, JIT-режим и пользовательские перегрузки `push` — прежним
путём (тест 306 требует JIT-экземпляра `push`). Побочно `active_key`/`memo_key` строятся только при разборе.
Тест: `tests/369_push_fast_path.vish` (проходит и на базе — поведение не изменилось).
